## Scope

Port the second sync verb natively, following the S1 forward-strangler pattern:

- `internal/sync/syncagent*.go`: flag parsing (byte-exact usage heredoc, exit-2
  contract), standalone target resolution + multi-target fan-out (banner,
  `--resolved-config-only` seam, per-target nested runners, stop on first
  failure), single-target runner (materialize fallback + `RECIPE_MCP_TEMP:`
  seam, flatten/merge via `internal/skills` + `internal/projectcache`, cache
  paths via `internal/projectcache`), `ensure_target_workspace`, agent
  selection with the D24 path, platform agent matrix from
  `lib/_internal/platform.sh` (8 agents), `sync_one_agent` with D3 (commands
  dir never `rm -rf`; unlink-through-symlink), D22 (no hooks unless
  `--resolved-hooks`), hard refusal on non-symlink occupancy for instructions
  links, relative instructions symlinks, absolute skills symlinks.
- `internal/sync/sync.go`: replace the `bash lib/sync-agent.sh` exec in the
  `sync` fan-out with the native nested runner (fanout wiring only).
- `internal/cli/cli.go`: native `sync-agent` route replacing the shim.

Constraints:

- Materialize JSON seams (`--recipe-mcp-out`, `--resolved-config-out`,
  `--resolved-hooks-out`) unchanged; the runner still execs
  `recipe-materialize.py` until S14 lands.
- No shell file deletion (S16 owns it); no edits to shared gates, go.mod,
  `recipe-materialize.py`, the plan doc, or generated ai-specs config.
