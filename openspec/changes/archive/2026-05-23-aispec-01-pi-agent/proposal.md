# Proposal: Add Pi Agent Target

## Intent

Pi (pi.dev) is not supported as a `sync-agent` target. The fan-out pipeline distributes skills, MCPs, and commands to claude, cursor, and opencode — Pi needs the same treatment. Fan-out via `sync-agent` replaces the abandoned `@ai-specs/pi` extension.

## Scope

### In Scope
- Register `pi` in `lib/_internal/platform.sh` with correct paths
- Add `--pi` flag to `lib/sync-agent.sh` argument parsing + usage help
- Update agent comment in `ai-specs/ai-specs.toml`
- Ensure `--all` includes Pi when enabled

### Out of Scope
- Recipe support for Pi (Pi has no recipe concept — future extension)
- Commands/agents for Pi (Pi uses extensions, not slash commands)
- `@ai-specs/pi` extension maintenance (deprecated in favor of fan-out)

## Capabilities

### New Capabilities
- `pi-agent-target`: syncing ai-specs skills and MCPs to Pi via `sync-agent --pi`

### Modified Capabilities
- `project-doctor`: Pi must be recognized as valid agent in enabled-agent validation

## Approach

Pi aligns with OpenCode's fan-out pattern:
- **Skills**: symlink `RESOLVED_SKILLS_DIR/` → `.pi/skills/`
- **MCP**: `.mcp.json` with `mcpServers` key (same as claude/cursor)
- **AGENTS.md**: natively supported — no symlink
- **No commands**: Pi uses extensions

Platform entry: `skills_dir=.pi/skills`, `mcp_config_path=.mcp.json`, `mcp_key=mcpServers`, `native=true`, empty for `instructions_path`, `agents_dir`, `commands_dir`.

## Affected Areas

| Area | Impact | Description |
|------|--------|-------------|
| `lib/_internal/platform.sh` | Modified | Add `pi` case block |
| `lib/sync-agent.sh` | Modified | Add `--pi` flag, update usage + help text |
| `ai-specs/ai-specs.toml` | Modified | Add "pi" to supported agents comment |
| `.gitignore` | Modified | Add `.pi/skills/` |

## Risks

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| pi-mcp-adapter diverges from claude MCP behavior | Low | Same `.mcp.json` format; adapter v2.7.0 validated |
| `.pi/skills/` not recognized by Pi | Low | Pi docs confirm project-local path |
| Existing agent fan-out breaks | Low | New case + flag only; shared logic unchanged |

## Rollback Plan

Remove `pi` case from `platform.sh`, `--pi` flag from `sync-agent.sh`, and comment update from `ai-specs.toml`. Delete any generated `.pi/skills/` symlink.

## Dependencies

- `pi-mcp-adapter` v2.7.0 installed globally (already done)
- `.mcp.json` already generated by existing pipeline

## Success Criteria

- [ ] `ai-specs sync-agent --pi` runs fan-out without errors
- [ ] `ai-specs sync-agent --all` includes Pi when in `[agents].enabled`
- [ ] `.pi/skills/` created with symlinks to resolved skills
- [ ] `.pi/skills/<name>/SKILL.md` exists and points to correct skill
- [ ] `.mcp.json` generated/updated with MCPs (via pi-mcp-adapter)
- [ ] `ai-specs doctor` recognizes pi as valid agent
- [ ] Existing agents (claude, opencode) unaffected
- [ ] Manual test: `ai-specs sync-agent --all` in ai-specs-cli repo
