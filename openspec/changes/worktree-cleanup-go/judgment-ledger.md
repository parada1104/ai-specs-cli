## CONFIRMED — both judges

### C1 — a test that passes only because of where it runs (BLOCKER, both)
`gate/cleanup_test.go:12-24`

`TestCleanupModeIsRegistered` asserts exit 2, which holds only because the dev
checkout is a linked worktree. `requirePrimaryCleanupCheckout` refuses only when
`absolute-git-dir != git-common-dir`; in a plain clone they are equal.

**Reproduced by the coordinator**, not accepted on reasoning. Cloned the branch
into a plain checkout (what `actions/checkout@v4` produces):

```
absolute-git-dir: .../ciclone/.git
git-common-dir  : .git
--- FAIL: TestCleanupModeIsRegistered
    cleanup_test.go:22: cleanup from linked worktree exit = 0, want 2
```

`.github/workflows/release-worktree-gate.yml` runs `go test ./...` on every `v*`
tag push, and it is the only workflow in the repo. This breaks the release build
before the binaries are built, so a tagged release would publish zero assets.

Same class as the defects this session already produced: a test that passes on a
property of the environment rather than of the code.

### C2 — cleanup aborts the whole pass on the first error (CRITICAL, both)
`gate/cleanup.go:426-437`

Each destructive helper's error does `return err` from inside
`for _, record := range records`, so one failure abandons every remaining
eligible worktree in that pass — no output line, no status, no signal.

**This violates the change's own spec.** `specs/worktree-flow/spec.md:198`:
"it MUST not stop after the first candidate".

Judge A added the consequence that makes it likely rather than theoretical:
`removeRemoteBranchCleanup` runs `git push --delete` with no pre-check that the
remote ref still exists, so an ordinary already-deleted remote branch (deleted
earlier through the GitHub UI) becomes a hard error that aborts the pass.

Untested: `TestCleanupDryRunVisitsEveryCandidate` only covers the all-success
dry-run path, where the loop `continue`s before any deletion can fail.

### C3 — the destructive mode inherits the gate's fail-open (CRITICAL, both)
`gate/main.go:66-72`

A flag-parse error prints a warning and returns **exit 0** before the `--cleanup`
dispatch is reached. The gate fails open deliberately because it is
non-destructive; cleanup is destructive and must not inherit that.

Reachable by version skew: an older cached binary without `-cleanup`, invoked by
the new launcher, reports success while doing nothing — indistinguishable from a
legitimate no-op.
